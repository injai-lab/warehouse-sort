# 첫 상자 분류 후 준비 위치 이동 — 별도 실험 모드

새 학습 없이 기존 최고 EMA 모델을 사용한다. 기존 full/demo70/model70 메뉴는 유지한다.
새 메뉴는 **실험 · 첫 분류 후 준비 이동 (1회)** (`prepare`)이다.

## 화면에서 실행

현재 서버의 8765 포트를 VS Code에서 **Private**으로 전달하고 페이지를 Ctrl+Shift+R로 갱신한다.
실행 방식에서 새 실험 모드를 선택하고 **시작 / 계속**을 누른다. 메뉴 선택은 초기 상태에서 일시정지한다.
관람 환경은 시드 100000 하나이며, 화면에 다음 제어 주체를 표시한다.

- **학습 모델 제어**: 기존 EMA, DDPM 100회, 행동 묶음 8개, 최근 실제 관측 2개.
- **스크립트 제어**: 집게 열기 → 수직 상승 → 높은 위치에서 수평 이동 → 준비 높이로 하강.
- 준비 단계와 진행 스텝, 실패 시 사유도 표시한다. 준비 실패 이후 시작 버튼은 비활성화한다.

서버를 새로 시작할 때(기존 서버가 있으면 먼저 종료):

```bash
cd '/home/student/projects/Robot Parcel Sorting Challenge'
WAREHOUSE_GPU=0 scripts/run_v100.sh scripts/live_viewer.py --port 8765 --mode prepare
```

종료는 Ctrl+C 또는 `kill -INT "$(cat runs/live-viewer.pid)"`.
`--mode`를 생략하면 기존과 같이 시범 70 복원 모드에서 시작한다.
공개 포트, 새 시스템 패키지, 학습은 필요하지 않다.

## 실행 흐름과 수정 위치

### `scripts/live_viewer.py` — 환경과 모델 실행 연결

`make_env(mode)`는 새 모드에만 환경 1개와 400스텝 한도를 설정한다. 기존 모드는 환경 4개/200스텝이며 시범 재생은 45스텝에서 멈춘다. 환경 개수가 달라지는 메뉴 전환 때만 환경을 다시 만든다.

에피소드 시작의 `env.reset()`은 일반 초기화이다. **첫 상자 분류 후 준비 동작 중에는 reset, set_state_dict, set_pose, set_qpos 등을 호출하지 않는다.** 새 prepare 모드의 초기화도 시범 상태 복원을 사용하지 않는다.

1. 기존 모델의 `get_action(obs)`로 행동을 만들고 `env.step(action)`으로 실행한다.
2. `_placed_correct`에서 처음 정분류된 상자를 감지한다. 실제 환경 판정은 올바른 통 범위 안에 놓였고 잡고 있지 않은 상태이다. 한 번 개입한 뒤 다시 개입하지 않는다.
3. `sequence=None; cursor=0`으로 남은 모델 행동을 버린다.
4. 스크립트가 만든 `(1,4)` 정규화 행동을 같은 `env.step()`에 전달한다.
5. 준비 종료 후 다음 반복에서 새 `get_action(obs)`를 호출한다. 기존 묶음을 재사용하지 않는다.

### `warehouse_sort/ready_intervention.py` — 준비 동작 설정과 제한

`ReadyIntervention`이 네 단계의 이동을 담당한다.

| 설정 | 현재 값 / 의미 |
|---|---|
| 참고 데이터 | traj_0의 70스텝 손끝 XYZ만 이동 목표로 사용 |
| 준비 목표 | 약 `(0.055284, 0.005043, 0.220642)`m, 월드 좌표 |
| 상승 높이 | 최소 0.32m, 현재 손끝·상자 높이와 목표 위 0.10m 여유를 고려 |
| `MAX_DELTA` | 명령당 최대 0.012m; 제어기 응답으로 실제 이동량은 더 작음 |
| `TOLERANCE` | 목표와 거리 0.008m 이내 |
| 단계 도달 확인 | 집게가 열리고 목표 거리 조건을 연속 3스텝 만족 |
| `MAX_STEPS` | 전체 준비 최대 180스텝; 현재 20Hz 제어에서 시뮬레이션 9초 |

Panda의 `pd_ee_delta_pos`는 root 좌표 XYZ 이동과 집게 명령만 제공한다. 현재 root 회전이 단위 회전인지 검사하고, 위치 명령 범위 ±0.1m에 맞춰 이동량을 정규화한다. 집게 `+1`은 열린 상태 0.04m를 명령한다.

시범의 관절 각도와 손목 회전을 정확히 재현하는 기능은 아니다. **시범의 손끝 위치를 참고한 준비 이동**이며 손목 회전은 기존 위치 제어기의 방식으로 유지된다. 시범 관절 값은 출처 확인용 로그로만 기록한다.

높이 여유를 두고 먼저 상승한 뒤 수평 이동하는 보수적 경로이다. 로봇 전체 링크의 충돌 없는 경로를 수학적으로 보장하는 모션 플래너는 아니다. 상자와 통의 상태를 덮어쓰지 않으며, 물리 시간 경과에 따른 자연스러운 움직임은 계속될 수 있다.

180스텝 안에 도달하지 못하면 `failed`로 종료하고 모델을 재개하지 않는다. 이 제한은 실제 수행한 물리 스텝 기준이며 사용자의 일시정지 시간은 포함하지 않는다. 전체 실험 최대 400스텝은 **기존 200스텝 평가와 별도**이다.

### 실제 관측 유지

모델 입력은 `(1,2,54)`, 행동 묶음은 `(1,8,4)`, 실행 행동은 `(1,4)`이다.
스크립트 단계도 정상 `env.step()`을 사용하므로 FrameStack이 매 스텝 실제 관측을 갱신한다.

로그 검증은 매 스텝 다음을 확인한다.

- 최신 관측 프레임이 `base.get_obs()`와 일치.
- 이전 프레임이 직전 스텝의 최신 관측과 정확히 일치.
- 재개 시 모델에 넘기는 관측 2개를 `policy_input`으로 기록.

시범 관측 69/70을 모델에 주입하지 않는다. 준비 위치 읽기에 사용한 데이터와 모델 입력은 별개이다.

### `web/live-viewer/index.html` — 화면 표시

새 메뉴, 한 에피소드 선택 표시, 제어 주체와 준비 단계, 실패 시 실행 버튼 비활성화를 담당한다. 화면만 보고도 현재 행동이 모델에서 왔는지 스크립트에서 왔는지 확인할 수 있다.

## 기록과 검증

자세한 JSONL은 `runs/ready-intervention/ready-*.jsonl`에 남는다. 설정, 개입 시점, 버린 행동 수, 단계 전환, 실패 사유, 실제 관측 이력, 상자/통 자세, 행동과 제어 주체를 기록한다. 상세 로그는 Git에서 제외한다.

`scripts/check_ready_viewer.py`는 한 에피소드의 브라우저 통합 검사이다. 학습은 하지 않지만 실제 에피소드를 실행하므로 코드 읽기만 할 때는 실행하지 않는다. 기존 메뉴로 전환하는 검사는 추가 에피소드를 재생하지 않는다.

대량 평가나 여러 시드 성능 비교는 실행하지 않았다. 먼저 사용자가 화면에서 동작을 확인한 뒤 다음 실험을 결정한다.
