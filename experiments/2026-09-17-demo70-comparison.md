# 시범 70스텝 복원: 남은 시범 행동과 기존 최고 모델 비교

## 결과

**복원한 동일 상태에서 시범 재생과 기존 모델 모두 두 번째 파란 상자를 정분류했습니다.**
새 학습이나 모델 가중치 변경은 없습니다.

| 실행 | 두 번째 잡기(복원 후) | 두 번째 들기: 높이 >10cm | 두 번째 정분류 | 45스텝 시점 모두 정분류 | 최종 모두 정분류 |
|---|---|---|---|---:|---:|
| 남은 시범 행동 재생 | +10 | +24 | +45 | 4/4 | 4/4 (+45에 종료) |
| 같은 상태에서 기존 모델 | +10 / +10 / +10 / +10 | +73 / +38 / +45 / +73 | +91 / +58 / +66 / +91 | 0/4 | 4/4 (+200에 종료) |

시범 데이터 `traj_0`의 **하나의 동일한 상태를 네 병렬 환경에 복제**한 진단입니다.
새로운 장면 시드 4개나 독립적인 시범 4개를 시험한 결과가 아닙니다. 모델의 배치별 확산 노이즈가 달라 완료 시점이 달랐습니다.
분류 정확도는 두 경우 최종 8/8(100%)이지만, 원래 시작 상태에서의 20개 에피소드 평가 점수로 대체하면 안 됩니다.
동일한 45스텝 예산에서는 시범만 완료했고 모델은 더 오래 걸렸다는 점도 함께 기록합니다.

## 복원 검증 — 모델 실행 전에 시범으로 확인

1. 데이터 `traj_0`의 `env_states`에서 **70번 상태**를 읽었습니다. 이 상태는 행동 0–69를 실행한 뒤, 행동 70을 실행하기 전입니다.
2. 로봇 루트 자세·관절 위치·관절 속도, 상자·분류함 등의 자세·속도를 복원했습니다. 단일 환경 데이터의 `parcel_*_env0`을 각 환경의 해당 상자에 매핑했습니다.
3. 로봇 관절 속도를 없애는 `agent.reset()`은 사용하지 않았습니다. 컨트롤러 내부 목표를 복원된 관절 위치로 초기화하고 `use_target=False`를 확인했습니다.
4. H5에 포함되지 않은 작업 누적 플래그는 시범 0–70의 물체 위치·분류함 범위·잡기 해제로 재구성했습니다. 초기 정분류는 `[빨강=true, 파랑=false]`입니다.
5. 물리 상태에서 새로 계산한 54차원 관측과 저장된 70번 관측의 최대 절대 차이는 **9.91×10⁻⁷**이었습니다(검증 허용치 2×10⁻⁵).
6. FrameStack을 초기 상태 복제로 채우지 않고, 저장된 **69번·70번 관측**으로 정확히 채웠습니다.
7. 먼저 남은 시범 행동 **70–114, 45개**를 변경 없이 환경에 전달했습니다. 네 환경 모두 +10에 파란 상자를 잡고 +45에 정분류했습니다.
8. 다시 동일하게 복원한 뒤 기존 최고 EMA를 실행했습니다. 시범/모델 실행 직전의 물리 배열 해시와 관측 이력 해시가 각각 동일함을 assertion으로 확인했습니다.

시범 상태에는 물리 솔버의 접촉 캐시가 저장되지 않습니다. 이 시작점은 집게가 열린 비접촉 상태이고,
시범 연속 재생 성공으로 복원 방법을 기능적으로 검증했습니다. 미세 물리 궤적까지 원래 녹화와 비트 단위로 동일하다고 주장하지 않습니다.
에피소드 타이머는 복원 시 0으로 두어 **복원 후 200스텝** 예산을 부여했습니다. 로봇 상태/모델 관측에 경과 시간은 추가하지 않았습니다.

## 해석: 관찰과 추정

### 관찰

- 원래 초기 상태에서 실행한 대표 사례들은 첫 상자 이후 두 번째 상자 중심을 벗어나 빈 집게를 닫았습니다.
- 이번에는 두 번째 상자 바로 위의 정상 접근 상태에서 시작했고, **모델도 잡기→들기→운반→정분류까지 수행했습니다.**
- 모델은 시범보다 늦게 들어 올리고 늦게 분류했지만, 복원 후 200스텝 이내에는 네 번 모두 성공했습니다.

### 지지되는 가설과 한계

“모델이 두 번째 상자 작업을 전혀 학습하지 못했다”는 설명은 이번 관찰과 맞지 않습니다.
**첫 상자 처리 후 두 번째 상자에 접근하는 과정에서 시범과 다른 상태로 벗어나고, 그 상태에서 회복하지 못한다**는 설명을 지지합니다.
이번 개입은 집게 X 좌표 하나만 바꾼 것이 아니라 전체 물리 상태와 관측 이력을 함께 복원했으므로, 특정 좌표나 단일 제어 값만 원인이라고 확정하지 않습니다.
또한 시범과 동일한 출발 상태 하나에서 성공한 것이므로, 다양한 장면이나 접근 오차에 대한 일반화가 입증된 것은 아닙니다.

## 직접 실시간으로 비교

기존 VS Code 비공개 전달 포트 **8765**, 기존 브라우저 주소를 그대로 사용합니다.
페이지를 **Ctrl+Shift+R**로 새로고침한 뒤:

1. **실행 방식 → 시범 70 → 남은 시범 행동**을 선택하고 **시작 / 계속**을 누릅니다. 45스텝에 멈춥니다.
2. **실행 방식 → 시범 70 → 기존 모델**을 선택하고 **시작 / 계속**을 누릅니다. 최대 200스텝까지 실행합니다.
3. 관람 항목 **동일 상태 복제 1–4**를 바꾸면 각 환경을 볼 수 있습니다.
4. **처음부터**는 현재 선택한 방식의 시작 상태로 복원합니다. 진단 모드에서는 관측 이력과 추론 난수 시드도 다시 맞춥니다.
5. 원래 초기 상태와 비교하려면 **처음부터 → 기존 모델** 방식을 선택합니다.

관람은 저장된 영상을 재생하는 것이 아니라 시범 행동 또는 모델 출력을 실제 PhysX 환경에 적용합니다.
시범 모드에는 “모델 추론 없음”을 표시합니다. 모델과 물리 설정은 진단 스크립트와 같으며 영상 렌더러는 사용하지 않습니다.

## 코드와 명령

- `warehouse_sort/demo_restore.py`: 복원·제어기 정렬·69/70 관측 이력 검증(진단과 관람이 공유).
- `scripts/diagnose_demo70.py`: 시범 재생 성공 후 동일 상태 모델 비교. 시범 실패 시 모델 결과 해석 단계로 진행하지 않음.
- `scripts/live_viewer.py`: 두 관람 모드와 원래 시작 모드.
- `scripts/check_demo70_viewer.py`: 브라우저에서 두 방식의 완주·정분류·초기 자세 일치 검사.

```bash
WAREHOUSE_GPU=0 scripts/run_v100.sh scripts/diagnose_demo70.py
WAREHOUSE_GPU=0 scripts/run_v100.sh scripts/live_viewer.py --port 8765
```

진단 출력 폴더가 이미 있으면 덮어쓰지 않고 중단합니다. 기존 관람 서버가 실행 중이면 두 번째 서버를 띄우지 말고 현재 화면에서 방식을 선택하세요.
