# 첫 상자 정분류 후 준비 이동 — 단일 에피소드 기능 확인

## 범위

새 학습 없음. 기존 최고 EMA, state, DDPM 100회, 행동 묶음 8개, 실제 관측 이력 2개 유지.
기존 모드를 보존하고 `prepare` 모드만 추가했다. 이 모드는 시드 100000 한 환경에서 최대 400스텝을 실행하며 기존 200스텝 평가와 별개이다. 대량 평가 및 시드별 성공률 측정은 하지 않았다.

## 기능 확인 결과

| 시점 | 관찰 |
|---|---|
| 77스텝 | 빨간 상자 정분류 감지, 남은 예측 행동 3개 폐기 |
| 78–81 | 스크립트로 집게 열기 |
| 82–130 | 수직 상승 |
| 131–205 | 약 0.321m 높이에서 준비 위치 위로 수평 이동 |
| 206–227 | 시범 70스텝의 손끝 XYZ를 참고한 높이로 하강 |
| 227스텝 이후 | 실제 226·227스텝 관측 2개로 모델 재추론, 228스텝부터 모델 행동 |
| 266스텝 | 두 상자 모두 정분류 |
| 400스텝 | 전체 한도로 일시정지, 두 상자 정분류 유지 |

준비 동작은 150스텝(현재 제어 주기에서 시뮬레이션 7.5초)이다. 목표 `(0.055284, 0.005043, 0.220642)m`, 도달 손끝 `(0.054744, 0.005026, 0.221865)m`로 허용 오차 8mm 이내이다. 목표 관절 각도나 손목 회전 전체를 재현했다고 주장하지 않는다.

각 스텝에서 최신 관측과 환경의 현재 관측 일치, 관측 이력의 연속성을 검사했다. 재개 시 `policy_input`이 마지막 스크립트 스텝에서 반환된 실제 관측 이력과 정확히 일치했다. 시범 관측 주입, 준비 중 env.reset/물리 상태 강제 설정 없음. 상자와 통에 어떤 setter도 호출하지 않는다. 준비 전후 통 자세는 동일했으며 상자는 물리 시간 경과에 따라 조금 움직였다. 상세 위치 변화는 결과 JSON에 기록했다.

## 첫 확인의 제한 시간 중단도 보존

처음에는 준비 한도를 100스텝으로 설정했다. 약 12mm 이동 명령에 대한 실제 응답은 이보다 작아서 수평 이동 중 177스텝에 제한 시간이 만료됐다. 모델을 재개하지 않고 `aborted`로 멈췄으며 UI 시작 버튼도 비활성화됐다.

이동 속도와 경로를 유지하고 준비 한도를 180스텝으로 늘린 뒤 **같은 시드 하나를 재확인**하여 위 결과를 얻었다. 실패 기록은 결과 JSON의 `initial_timeout`에 보존했다. 두 번의 기능 확인을 여러 에피소드 성공률로 계산하지 않는다.

## 화면 검증

Playwright Chromium으로 실제 화면을 열고 다음을 확인했다.

- `스크립트 제어` 표시 및 원본 로봇 메시 화면.
- 준비 종료 뒤 모델 재개와 최종 두 상자 정분류.
- 브라우저 오류 0.
- 기존 full/demo70/model70 모드 전환 및 4개 환경 표시 유지(추가 재생 없음).
- prepare로 돌아와 환경 하나, 0스텝, 일시정지 상태.

사용자 PC에서의 최종 육안 확인은 아직 하지 않았다. 현재 서버는 prepare 모드로 일시정지해 둔다. 사용자 확인 전에 대량 평가는 시작하지 않는다.

## 코드 및 실행

[실행·설정 안내](../docs/READY_INTERVENTION_KO.md), [결과 JSON](ready-intervention-single-results.json).

- `warehouse_sort/ready_intervention.py`: 정상 행동 기반 준비 제어, 시범 목표 읽기, 도달/시간 제한, 수치 로그.
- `scripts/live_viewer.py`: 새 모드, 남은 행동 폐기, 모델 재개, 환경 크기 전환.
- `web/live-viewer/index.html`: 새 메뉴, 제어 주체/단계 표시.
- `scripts/check_ready_viewer.py`: 단일 에피소드 브라우저 기능 검사.

```bash
WAREHOUSE_GPU=0 scripts/run_v100.sh scripts/live_viewer.py --port 8765 --mode prepare
```

포트는 127.0.0.1:8765만 사용하고 기존 VS Code Private 전달을 유지한다. 모든 상세 관측 로그와 스크린샷은 `runs/ready-intervention/`에 보관하며 Git에서 제외한다. 코드 구문 검사와 `git diff --check` 통과.
