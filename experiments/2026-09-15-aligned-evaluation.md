# Easy/state: 학습 중 평가와 독립 평가의 추론 설정 정렬

## 목적과 보존 범위

새 학습 없이 기존 최고 체크포인트의 EMA 가중치로 재평가했습니다.
기존 독립 평가 결과와 모델을 수정하지 않고 새 출력 폴더를 사용했습니다.

- 모델: `il/baselines/diffusion_policy/runs/warehouse_state_dp_easy_full_30k/checkpoints/best_eval_sort_accuracy.pt`
- 모델 갱신 수: 10,001
- SHA256: `131f25d665933d4ff5e452c5909b60f56cedc902d6ee45a3fda747afd2401527`
- 기존 결과: `runs/easy-full-final-eval/metrics.json`
- 새 결과: `runs/easy-full-aligned-eval/metrics.json`
- 환경 시드: 기존과 같은 **100000–100019**, 총 20개
- 전역 Python/NumPy/PyTorch 시드: **20260915**, 기존 독립 평가와 동일
- GPU 0 한 대, 병렬 환경 4개, state/easy, 영상 없음

## 결과

| 평가 방식 | 정분류 택배 / 전체 | 분류 정확도 | 두 택배 모두 정분류한 에피소드 |
|---|---:|---:|---:|
| 기존 독립 평가: 16회 제거, 한 행동씩, 199스텝 | 14/40 | 35.0% | 0/20 |
| 정렬 평가: 100회 제거, 8개 행동씩, 199스텝 | 20/40 | 50.0% | 0/20 |
| 정렬 평가: 100회 제거, 8개 행동씩, 200스텝 | 20/40 | 50.0% | 0/20 |

분류 정확도는 **35% → 50%, +15%p**로 증가했고 정분류 택배는 **6개** 늘었습니다.
그러나 이번에는 모든 에피소드에서 정확히 1개씩 정분류했으며, 두 개 모두 정분류한 에피소드는 여전히 0개입니다.
199스텝과 200스텝의 결과가 같아 마지막 한 스텝은 이번 점수 차이를 설명하지 않습니다.

평가 시간: **176.92초**. 이전 독립 평가 시간은 220.85초였습니다.
이번 시간에는 실행 중 검증과 환경 초기화가 포함되어 있으므로 정밀한 추론 속도 벤치마크는 아닙니다.

[기계 판독 가능한 결과와 20개 시드별 기록](easy-full-aligned-results.json)을 함께 보관합니다.
`both_correct_episodes`는 실행 중 수집한 에피소드별 정분류 개수로 후처리했으며 추가 rollout은 없습니다.

## 확인한 코드 차이와 적용 방법

| 항목 | 기존 독립 평가 | 학습 중 평가 / 이번 적용 |
|---|---|---|
| 모델 가중치 | EMA | 같은 EMA, strict 로딩 |
| DDPM 노이즈 제거 | 16회 | **100회**, timesteps 99→0 |
| 예측 길이 | 16 | 16 유지 |
| 행동 실행 | 매 스텝 다시 예측, 예측 배열 인덱스 1의 행동 하나 실행 | **인덱스 1:9의 행동 8개 연속 실행**, 다음 구간 재예측 |
| 관측 이력 | 정책이 이전/현재 상태를 보관 | **학습기의 FrameStack 2프레임을 그대로 사용** |
| 구간 실행 중 이력 | 매 정책 호출마다 갱신; 기존은 매 스텝 호출 | **8개 행동을 실행하는 중에도 매 물리 스텝 갱신** |
| 시작 시 관측 | 초기 상태 복제 | FrameStack.reset으로 초기 상태 복제; 의미상 동일 |
| 에피소드 경계 | 명시적 환경 reset 후 policy.reset | 학습기의 환경/FrameStack reset과 200스텝 자동 reset; 이전 행동 구간 폐기 |
| 환경 생성 | 독립 make_env, reconfiguration_freq 기본 0 | 학습기의 make_eval_envs, reconfiguration_freq=1과 시범의 scene kwargs 사용 |
| 종료 시점 | 실제 199스텝 | **200스텝 truncation**. 199스텝 결과도 함께 수집 |
| cuDNN 결정성 | 별도 설정 없음 | 학습 체크포인트의 torch_deterministic=true 적용 |
| 결과 읽기 | reset 전 base.evaluate | 200스텝 자동 reset **직전 final_info** |

새 스크립트는 학습기의 `Agent.get_action()`과 `make_eval_envs()`를 직접 재사용합니다.
`train.py`를 별도 모듈 이름으로 import하며 `__main__` 아래 학습 코드와 optimizer는 실행하지 않습니다.
학습 때 사용한 네트워크 구조는 체크포인트의 args로 복원합니다.

학습 중 평가는 처음 reset과 이후 자동 reset의 난수 흐름을 사용했습니다.
이번에는 지정된 20개 시드를 정확히 지키기 위해 매 4개 에피소드 배치 시작에 명시적으로 seed를 전달합니다.
학습 당시의 8개 병렬 환경/16개 에피소드 대신, 이전 독립 평가의 4개/20개를 유지했습니다.
따라서 학습 당시 46.875% 자체를 재현하는 실험이 아니라 **같은 독립 평가 시드에서 학습기의 추론 프로토콜을 적용하는 실험**입니다.

## 성공 지표의 의미

공식 `env.py`의 `all_placed`/`success`는 올바른 분류와 잘못된 분류를 합산해 모든 택배가 놓였는지 판단합니다.
따라서 요청한 **두 상자 모두 성공**은 에피소드별 `success_count == 2`로 별도 계산합니다.
기존 평가는 all_placed가 0이므로 두 상자 정분류도 0입니다. 오분류도 0이었습니다.
이전에 작성한 실습 안내의 지표 설명도 이 구분을 반영해 정정했습니다.

## 검증

실제 평가 중 다음 조건을 assertion으로 확인했습니다.

- 100개 scheduler timestep, 8개 행동 묶음, 유한한 행동 값.
- reset 직후 관측 `(4, 2, 54)`와 두 초기 프레임의 일치.
- 매 물리 스텝마다 이전 최신 관측이 다음 관측 이력의 첫 프레임이 됨.
- 200스텝에서 네 환경 동시 truncation, 자동 reset 이후 초기 프레임 일치.
- 에피소드당 25번 행동 구간 생성, 이전 에피소드의 미실행 행동을 재사용하지 않음.
- 시범 생성 시드와 평가 시드가 겹치지 않음.
- 평가 전후 기존 결과 파일과 체크포인트 SHA256이 변하지 않음.

초기 실행에서 시범 JSON의 필드를 `seed`로 잘못 참조해 `KeyError: 'seed'`가 발생했습니다.
실제 메타데이터 필드 `episode_seed`로 수정했습니다. 오류는 시뮬레이터 평가 시작 전 발생했으며,
실패 로그는 `runs/easy-full-aligned-eval-preflight-error.log`에 보존했습니다.
기존 Vulkan 경고는 남아 있지만 렌더링 없이 물리 평가를 수행합니다.

## 실행 명령

프로젝트 루트에서:

```bash
WAREHOUSE_GPU=0 scripts/run_v100.sh scripts/eval_easy_aligned.py \
  > runs/easy-full-aligned-eval.log 2>&1
```

스크립트는 기존 출력 폴더가 있으면 중단합니다. 재실행하려면 스크립트의 출력 경로와 로그 경로를 새 이름으로 변경하세요.
데이터, 모델, 상세 로그는 Git에서 제외하고 결과 요약과 에피소드별 수치만 기록합니다.

## 해석 범위

이번 비교는 노이즈 제거, 행동 묶음, 환경/이력 처리 등 여러 조건을 함께 맞춘 결과입니다.
개별 변경의 효과를 분리한 실험이 아니므로 변화가 특정 설정 하나 때문이라고 단정할 수 없습니다.
난수 시드가 같아도 추론 횟수가 바뀌면 소비하는 난수 수와 순서가 달라집니다.
easy의 물체 배치는 고정되어 있으므로 새로운 배치에 대한 일반화 성능을 뜻하지 않습니다.
