# 두 번째 상자 실패 진단 — 기존 최고 모델, 새 학습 없음

## 결론

대표 4개 에피소드에서는 **두 번째 상자로 돌아오는 동작은 시작하지만, 접근 위치를 맞추지 못한 채 낮게 내려가 빈 집게를 닫고, 이후 회복하지 못했습니다.**
두 번째 상자에 대한 실제 잡기 신호가 0회이고 상자가 들리지 않았으므로, 확인된 실패 지점은 **접근 정렬 → 잡기 진입**입니다. 운반 단계에는 도달하지 못했습니다.
600스텝까지 늘려도 결과가 같아 이 네 에피소드의 실패를 단순한 200스텝 시간 부족으로 설명하기 어렵습니다.

## 실행 조건과 원본 보존

- 새 학습·가중치 변경 없음. 기존 최고 EMA 체크포인트, 10,001회 갱신 시점.
- SHA256: `131f25d665933d4ff5e452c5909b60f56cedc902d6ee45a3fda747afd2401527`.
- 기존 정렬 평가와 같은 학습기 `Agent`, DDPM 100회, 행동 묶음 8개, 관측 이력 2프레임.
- 기존 평가의 첫 배치인 **100000, 100001, 100002, 100003**을 대표 사례로 선택. 결과를 본 뒤 고른 사례가 아닙니다.
- 전역 난수 시드 20260915, GPU 0 한 대, 병렬 환경 4개, 영상 없음.
- 600스텝 연속 실행 중 200/400/600스텝을 기록. 환경 자동 reset만 꺼서 마지막 물리 상태를 보존하고 중간에 에피소드가 재시작되지 않도록 했습니다.
- 기존 20개 에피소드의 200스텝 점수는 변경하지 않습니다. 기존 결과 파일과 모델의 SHA256이 변하지 않았음을 확인했습니다.
- 진단 rollout 및 로그 저장 시간 약 **102.85초**. 매 스텝 숫자 계측을 포함한 시간입니다.

## 1. 직접 관찰한 사실

택배 번호 0은 빨강, 1은 파랑입니다. 파란 상자의 초기 중심은 약 `(0.056, 0, 0.031)`m이고, 바닥에 안정화된 높이는 약 `0.030`m입니다.
빨간 분류함 중심은 `(0, 0.36, 0)`m, 파란 분류함은 `(0, -0.36, 0)`m입니다.

| 시드 | 빨간 상자 첫 정분류 스텝 | 이후 파란 상자와 집게의 최소 수평 거리 | 파란 상자 잡기 횟수* | 파란 상자 최대 높이 | 600스텝 결과 |
|---:|---:|---:|---:|---:|---|
| 100000 | 77 | 4.65cm | 0 | 3.00cm | 빨강만 정분류 |
| 100001 | 80 | 5.62cm | 0 | 3.00cm | 빨강만 정분류 |
| 100002 | 125 | 4.78cm | 0 | 3.00cm | 빨강만 정분류 |
| 100003 | 149 | 4.05cm | 0 | 3.00cm | 빨강만 정분류 |

*정확히는 매 스텝 `agent.is_grasping(parcel_1)`이 true인 관측 수입니다. 첫 정분류 이후부터 600스텝까지 집계했습니다.
최소 수평 거리와 아래 최소 3차원 거리의 시점은 다를 수 있습니다.

- 첫 분류 후 집게가 빨간 분류함의 Y≈0.31–0.34m에서 작업대 Y≈0으로 돌아옵니다. 따라서 “두 번째 상자 쪽으로 전혀 이동하지 않음”은 아닙니다.
- 그러나 파란 상자는 X≈0.056m에 있는데 집게 X는 대체로 0 부근으로 돌아옵니다. 접근 중 집게 높이가 약 0.01–0.03m까지 내려가는 사례도 있습니다.
- 집게를 닫기 시작하는 상태는 각각 100, 102, 150, 170스텝입니다. 기준은 첫 정분류 이후 다음 gripper 명령이 처음으로 -0.5 미만인 상태입니다.
- 200→600스텝의 gripper 명령은 네 사례 모두 **100% -0.5 미만**입니다. 집게 두 관절은 200·600스텝에 약 0m로 닫혀 있지만, 어느 상자도 잡고 있지 않습니다.
- 파란 상자의 최대 위치 변화는 초기 낙하 안정화 약 1mm뿐이고, 높이가 증가하지 않습니다. 파란 분류함으로의 운반은 관찰되지 않았습니다.

### 대표 숫자 로그: 시드 100000

위치는 m 단위입니다. 명령은 **해당 상태에서 다음 스텝으로 보낸 명령**이며 gripper +1은 열기, -1은 닫기 방향입니다.
정분류 여부는 누적 판정이며, 물체 위치도 함께 기록했습니다.

| 상태 스텝 | 집게 XYZ | 파란 상자 XYZ | 다음 집게 명령 | 실제 파랑 잡기 | 빨강/파랑 정분류 |
|---:|---|---|---:|---|---|
| 77 | (-0.0273, 0.3441, 0.0911) | (0.0560, 0, 0.0300) | +0.786 | false | true / false |
| 100 | (0.0018, 0.0171, 0.0315) | (0.0560, 0, 0.0300) | -1.000 | false | true / false |
| 120 | (0.0031, 0.0063, 0.0446) | (0.0560, 0, 0.0300) | -0.981 | false | true / false |
| 200 | (-0.0026, -0.0254, 0.0654) | (0.0560, 0, 0.0300) | -0.968 | false | true / false |
| 600 | (-0.0167, -0.0270, 0.0606) | (0.0560, 0, 0.0300) | 종료 | false | true / false |

100스텝에서 보낸 전체 행동 명령은 약 `[0.0054, 0.0305, -0.0011, -1.0000]`입니다.
120스텝의 두 손가락 관절은 각각 약 0m입니다. 가까이 갔다고 판정할 수 있는 순간에도 실제 파랑 잡기는 false입니다.

[네 사례의 주요 시점 CSV](second-parcel-keyframes.csv)에는 두 상자 각각의 위치·정분류 여부, 집게 XYZ·네 행동 명령·손가락 관절, 상자별 잡기 상태를 기록했습니다.
로컬 `trace.jsonl`에는 **4개 에피소드 × 601개 상태 = 2,404행**의 전체 숫자 로그가 있습니다.
이 로컬 로그의 `action_leading_to_state`는 해당 상태를 만든 직전 행동입니다. CSV의 `next_*`와 시간 기준이 다름을 명시합니다.

## 2. 시범의 두 번째 상자 구간과 비교

시범 **200개 전체**의 관측 및 actor 위치를 분석했습니다. 관측의 상자 위치가 저장된 actor 위치와 일치하는지도 확인했습니다.
시범에는 상자별 접촉 판정이 없고 aggregate `is_grasped`만 있으므로, 시범의 잡기 시점은 **두 번째 상자 근처 + 잡기 신호**로 추정합니다.
정분류 시점 역시 올바른 분류함 내부 좌표·높이와 aggregate 잡기 해제를 이용한 추정이며, 모델의 직접 판정과 구분합니다.

| 단계 | 시범 200개에서의 시점 | 모델 대표 4개 |
|---|---|---|
| 첫 상자 정분류 | 모두 약 55 | 77 / 80 / 125 / 149 |
| 두 번째 상자로 이동 시작 | 대표 시범 60 | 돌아오기는 하지만 중심 X와 높이가 시범에서 벗어남 |
| 두 번째 상자에 6cm 이내 접근 | 모두 77 | 3D 최단 거리 약 5.18–5.72cm, 실제 잡기 없음 |
| 두 번째 잡기 신호 | 모두 약 80 | 600스텝까지 없음 |
| 두 번째 상자 높이 10cm 초과 | 모두 94 | 없음, 3cm에 머묾 |
| 두 번째 정분류 | 모두 약 115 | 없음 |

시범 `traj_0`은 60스텝에 집게를 연 채 상승하며 이동합니다.
70스텝의 집게는 약 `(0.055, 0.005, 0.221)`m로 파란 상자 위에 위치한 뒤 내려옵니다.
77스텝에는 `(0.0496, 0.0003, 0.0723)`m, 집게는 열린 상태이고, 80스텝에 잡기 신호가 나타납니다.
반면 모델은 X≈0 부근으로 돌아오면서 이미 매우 낮게 내려갑니다. 이는 단순히 같은 시범 동작을 느리게 수행하는 양상과 다릅니다.

추가 데이터 관찰:

- 200개 중 전체 관측 배열과 행동 배열의 바이트 단위 고유값은 각각 **4종류**뿐입니다. 시범 개수에 비해 궤적 다양성이 작습니다.
- 23,000개 행동 중 6,800개는 팔 명령 성분 하나 이상이 [-1, 1] 밖입니다. 환경 제어기는 이를 clip하지만 현재 학습기는 원시 시범 행동을 그대로 학습하고 DDPM은 clip_sample=True를 사용합니다.
- 두 항목은 확인된 데이터/구현 특성입니다. 이것이 이번 실패의 원인이라는 인과관계는 아직 검증하지 않았습니다.

## 3. 시간 부족 진단 — 기존 점수와 별도

| 구분 | 에피소드 수 | 길이 | 정분류 택배 | 두 택배 모두 정분류 |
|---|---:|---:|---:|---:|
| 기존 정렬 평가, 보존 | 20 | 200 | 20/40 (50%) | 0/20 |
| 이번 대표 사례 진단 | 4 | 200 스냅샷 | 4/8 (50%) | 0/4 |
| 같은 사례 연속 실행 | 4 | 400 스냅샷 | 4/8 (50%) | 0/4 |
| 같은 사례 연속 실행 | 4 | 600 | 4/8 (50%) | 0/4 |

600스텝 결과는 새로운 20개 에피소드 점수로 취급하지 않습니다.
가장 늦게 첫 상자를 분류한 시드 100003도 이후 451스텝을 더 실행했지만 파란 상자를 잡지 못했습니다.
따라서 **이 네 사례에서는 시간을 세 배로 늘리는 것만으로 해결되지 않았습니다.** 무제한 시간에서도 절대 성공하지 못한다는 뜻은 아닙니다.

## 4. 원인 추정 — 사실과 구분

가장 직접적인 가설은 **첫 분류에서 누적된 위치·높이 오차로 시범과 다른 상태에 진입하고, 두 번째 상자의 접근/잡기 동작을 제대로 복구하지 못하는 것**입니다.
근거는 잘못된 접근 X, 너무 낮은 집게 높이, 빈 집게 닫힘, 이후 400스텝 동안 재시도 없이 닫힘 명령이 유지되는 현상입니다.
시범의 낮은 다양성도 복구 행동 부족과 일치하지만, 로그만으로 모델 내부 원인을 확정할 수는 없습니다.
“두 번째 상자 처리 자체를 전혀 학습하지 못함”과 “시범에 가까운 상태에서는 가능하지만 접근 오차에 취약함”은 아직 구분하지 못했습니다.

## 5. 다음 실험 하나 — 제안만, 아직 실행하지 않음

**같은 모델을 시범의 두 번째 상자 접근 직전 상태에서 시작하는 진단**을 제안합니다.

- 시범 70스텝의 물리 상태(첫 상자 분류 완료, 집게가 두 번째 상자 위에서 열린 상태)를 복원합니다.
- 관측 이력도 시범 69·70스텝으로 맞추고, 제어기 상태/목표 일관성을 확인합니다.
- 기존 100회 DDPM/8개 행동 묶음 설정으로 200스텝을 실행해 파랑 잡기·들기·정분류 여부를 측정합니다.
- 성공하면 첫 분류 후 접근 과정의 상태 이탈이 주요 문제라는 가설을 지지합니다. 실패하면 적절한 출발 상태에서도 두 번째 잡기 이후 행동을 재현하지 못한다는 증거가 됩니다.

이는 새 학습 없이 두 가설을 좁히는 개입 실험이며, 정상 시작 상태의 평가 점수와 분리해야 합니다.
