## Setup issues and fixes

1. Official Pixi environment uses Python 3.12 and NumPy 2.4.6. Resolve a separate
   Python 3.10 environment with NumPy 2.2.6 and PyTorch 2.7.1+cu126 / torchvision 0.22.1+cu126.
   Keep official Pixi files unchanged as source provenance.
2. Broad extra-index installation repeatedly retried downloads. Interrupted the initial
   attempt, increased `UV_HTTP_TIMEOUT` to 300 and reduced concurrent downloads to 4.
   Switched to `--torch-backend cu126`, keeping non-PyTorch dependencies on PyPI.
3. A trial `tool.uv.sources` configuration did not apply to the pinned requirements input:
   `Because there is no version of torch==2.7.1+cu126 ... requirements are unsatisfiable.`
   Removed that configuration; the `--torch-backend cu126` resolver succeeded.
4. Initial unauthed HTTP file-list probe to `/api/v1/competitions/list/<slug>` returned
   HTTP 404; this does not establish whether the data exists. Use the official authenticated
   Kaggle SDK and `scripts/fetch_easy_state.py` instead.
5. Initial simulator import failed with
   `ImportError: libGL.so.1: cannot open shared object file: No such file or directory`.
   `ldd` also found missing libglib/libgthread. Downloaded Ubuntu libgl1/libglx0/libglvnd0
   1.7.0-1build1 and libglib2.0-0t64 2.80.0-6ubuntu3.8, verified package hashes and extracted
   them only under `.cache/runtime`. `scripts/run_v100.sh` adds that local library directory
   to LD_LIBRARY_PATH for the child process. No apt installation, system driver change,
   or shell-startup edit was made.
6. With those libraries available, upstream state initialization still failed at
   `_build_background` with `RuntimeError: failed to find a rendering device` because
   custom RenderMaterial objects were constructed even with render_backend=none.
   Guarded only material/visual creation with `scene.can_render()`. All collision geometry,
   actor poses, random-number draws, state observations, action space and scoring code remain
   unchanged. The corrected state probe passed.
7. Video probe reported missing Vulkan extensions and
   `Your GPU driver does not support Vulkan. You may not use the renderer for rendering.`
   No video was generated; GPU state simulation works independently. Graphics-driver
   provisioning for this container is still required to enable GPU rendering.
8. Original evaluation always records video, and the state trainer enables a renderer.
   Added explicit headless options while retaining original defaults. See setup guide.
